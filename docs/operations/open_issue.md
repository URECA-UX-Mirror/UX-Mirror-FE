# 미결정 항목

계약서에 없거나 정해지지 않은 항목이다. 프론트는 각 항목의 `임시 결정`으로 작업을 계속하고, 확정되면 해당 계약 문서를 고친 뒤 이 문서에서 항목을 지운다. 값이 달라지면 Adapter에서 흡수한다([프론트엔드 구조](../architecture/frontend-structure.md)).

| 역할 | 담당 |
| --- | --- |
| 에이전트 코어: 브라우저 | 이성집 |
| 에이전트 코어: 흐름·저장 | 정자비 |
| 실행 API (페르소나·목표 입력) | 장근창 |
| UX 분석·비교 | 정윤희 |
| 프론트엔드 | 권혁준 |

## 항목

<a id="oi-1"></a>
### OI-1 `experimentKey` 생성 규칙

- 계약서: `POST /api/runs` 요청에 필수이고 비교 쌍마다 고유하다(`§5.1`). 생성 주체와 형식은 정해지지 않았다.
- 임시 결정: 프론트가 첫 Run을 만들 때 생성하고 같은 실험의 두 번째 Run에 다시 쓴다. 형식은 불투명 문자열(`§3.4`)로 보고 시각 기반 값을 쓴다.
- 확인할 것: 프론트 생성이 맞는지, 형식 제한(길이·문자), 중복 시 응답(`EXPERIMENT_RUN_EXISTS`로 충분한지), 서버 발급으로 바꿀 계획 유무.
- 담당: 장근창.

<a id="oi-2"></a>
### OI-2 Run 목록 조회

- 계약서: 17.1의 API 목록에 Run 목록 조회가 없다.
- 화면 1의 "마지막 Run·분석 상태·목표 달성 상태"와 화면 3의 "다른 실행 보기"에 필요하다.
- 임시 결정: 이 브라우저에서 시작한 `runId`를 `localStorage`에 기록한다. 다른 브라우저나 저장소 초기화 뒤에는 목록이 비어 보인다.
- 확인할 것: 목록 API(`GET /api/runs` 등)의 필요 여부와 필터(`experimentKey`, `variant`), 저장된 실측 Run을 목록에 포함할지.
- 담당: 장근창(API), 정자비(저장 구조).

<a id="oi-3"></a>
### OI-3 도착 화면 스크린샷 조회

- 계약서: 목표 화면에 도착만 하고 모델 판단을 하지 않은 화면은 Step이 없고(`§15.3`), 스크린샷 API는 `stepId` 기준이다(`§17.7`).
- 경로의 마지막 노드(환불 신청 화면)의 이미지를 가져올 방법이 없다.
- 임시 결정: 해당 노드에 "도착 화면 이미지 없음"을 표시한다.
- 확인할 것: 도착 화면 이미지를 `PathVisit`에 참조로 줄지, 별도 endpoint를 둘지, 저장 여부.
- 담당: 정자비(저장), 장근창(API).

<a id="oi-4"></a>
### OI-4 폴링 간격

- 계약서에 값이 없다. 임시로 1초를 쓴다.
- 확인할 것: 권장 간격, 서버 부하 한도, 종료 직후 `/issues` 분석 완료까지의 예상 시간.
- 담당: 장근창.

<a id="oi-5"></a>
### OI-5 Run 단위 증감값 제공

- 계약서: `RunComparison`은 before/after 값만 있고 증감이 없다(`§15.8`). 화면 지표(`ScreenMetricComparison`)에만 `delta`가 있다(`§15.7`).
- 임시 결정: Run 단위 값(`navigationCost`, `stepCount`, `backCount` 등)은 before/after를 나란히만 표시한다.
- 확인할 것: Run 단위 `delta`를 서버가 줄지, 프론트가 정수 뺄셈만 표시해도 되는지, 비교 문구에 대한 정윤희의 기준.
- 담당: 정윤희.

<a id="oi-6"></a>
### OI-6 프리셋 응답에 없는 값

- 계약서: `GET /api/presets`는 `goals`와 `personas`만 준다(`§17.9`).
- 임시 결정: 사이트(MORO MARKET), 버전 표시 이름(`v1 (변경 전)`, `v2 (변경 후)`), 버전별 변경 내용 문구, `maxSteps` 범위(1~15)와 기본값(8)을 프론트 상수로 둔다.
- 확인할 것: 변경 내용 문구("메뉴 라벨: 이용정보")의 출처, 사이트·버전 정보를 프리셋에 포함할지.
- 담당: 장근창.

<a id="oi-7"></a>
### OI-7 저장된 실측 데이터 시연

- 계약서: `SAVED_MEASURED`는 과거 실제 호출 결과를 저장한 뒤 재생한 결과다(`§2.1`). 시연 방법은 정해지지 않았다.
- 임시 결정: 화면 배지로 `resultOrigin`만 표시한다.
- 확인할 것: 저장된 실측을 API로 제공하는 방법(`LIVE`와 섞이지 않게), 시연에 쓸 Run 고정 방식, 시연 중 `LIVE` 실행 가능 여부.
- 담당: 정자비.

<a id="oi-8"></a>
### OI-8 CORS와 다른 PC 주소

- 계약서에 없다. 프론트는 `http://localhost:5173`, 백엔드는 `http://127.0.0.1:8000`으로 가정한다.
- 확인할 것: FastAPI의 허용 출처 설정, 다른 PC에서 실행할 때 출처를 추가하는 방법, 응답에 절대 주소를 담지 않기로 할지.
- 담당: 장근창.

<a id="oi-9"></a>
### OI-9 계약서와 대조하지 못한 mock·타입 값

- 이 저장소에는 계약서 본문이 없고 문서에 정리된 값만 있다. 아래는 문서에 값이 없어 프론트가 가정한 것이다.
- `GET /api/health`: `status` 값과 `activeRun`의 필드. 프론트는 `activeRun.runId`만 쓴다(`src/api/dto/misc.ts`).
- mock 응답에 쓴 코드 문자열: 비교 불가 이유 `PAGE_NOT_VISITED_IN_AFTER`, `CANDIDATE_NOT_IN_BOTH`, 조건 검사 `code`(`SAME_GOAL` 등), 종료 사유 `GOAL_REACHED`·`MAX_STEPS_REACHED`, 오류 코드 `SERVICE_UNAVAILABLE`·`INTERNAL_ERROR`·`SCREENSHOT_NOT_FOUND`, Issue `evidence` 키(`normalizedEntropy`, `top2Margin`, `extraSteps`, `maxSteps`), `schemaVersion`.
- 임시 결정: 위 값은 `src/mocks/`와 `src/api/dto/misc.ts`에만 있다. 화면 코드는 코드 문자열로 분기하지 않고 모르는 값은 그대로 표시한다.
- 확인할 것: 각 값의 실제 형식. 계약서와 다르면 mock과 DTO만 고친다.
- 담당: 장근창(health, 오류 코드), 정윤희(비교 불가 이유, 조건 검사, `evidence`).
