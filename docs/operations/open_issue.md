# 미결정 항목

프론트가 임시 계약으로 먼저 작업하는 동안 확정이 필요한 항목이다. 항목이 정해지면 해당 계약 문서를 고치고 이 문서에서 항목을 지운다. 각 항목의 `임시 결정`으로 작업을 계속하며, 확정 값이 달라지면 Adapter에서 흡수한다([프론트엔드 구조](../architecture/frontend-structure.md)).

| 역할 | 담당 |
| --- | --- |
| 에이전트 코어: 브라우저 | 이성집 |
| 에이전트 코어: 흐름·저장 | 정자비 |
| 실행 API (페르소나·목표 입력) | 장근창 |
| UX 분석·비교 | 정윤희 |
| 프론트엔드 | 권혁준 |

상태 `협의 필요`는 확정 전, `임시 결정`은 프론트가 정한 값으로 진행 중, `확정`은 결정이 끝난 항목이다. 확정되면 항목을 지우므로 이 문서에는 `확정`이 남지 않는다.

## 항목

<a id="oi-1"></a>
### OI-1 `runId` 생성·형식

- 임시 결정: 서버가 발급하는 불투명한 문자열. `POST /api/runs`가 즉시 반환한다.
- 확인할 것: 생성 규칙과 형식(디자인 시안은 `#RUN-2025-084` 형태), 재시작 뒤에도 같은 값으로 조회되는지.
- 담당: 장근창(발급·반환), 정자비(저장).

<a id="oi-2"></a>
### OI-2 `experimentKey` 생성 주체·형식

- 임시 결정: 요청에 없으면 서버가 발급하고, 같은 실험의 두 번째 Run은 첫 Run의 `experimentKey`를 요청에 담는다.
- 확인할 것: 생성 주체(서버·프론트), 형식, 두 Run을 묶는 방식, 조건이 다른 Run을 같은 키로 묶을 수 있는지.
- 담당: 장근창, 정윤희(비교 단위).

<a id="oi-3"></a>
### OI-3 Run 상태값

- 임시 결정: `RUNNING`, `SUCCESS`, `MAX_STEPS`, `BLOCKED`, `TIMEOUT`, `ERROR`. 모르는 값은 진행 중으로 처리한다.
- 확인할 것: 실제 값 목록, `PENDING`(접수·실행 전) 필요 여부, `terminationReason` 값 목록, 사용자 취소 상태 유무.
- 담당: 장근창, 정자비.

<a id="oi-4"></a>
### OI-4 공통 응답·오류 형식

- 임시 결정: 성공은 본문 그대로, 오류는 `{ "error": { "code", "message" } }`.
- 확인할 것: 성공 응답 래핑 여부, 오류 코드 목록, FastAPI 기본 `422`(`detail`) 그대로 둘지, `POST /api/runs`가 202를 쓰는지.
- 담당: 장근창.

<a id="oi-5"></a>
### OI-5 폴링 간격·동시 실행 제한

- 임시 결정: 폴링 2초(확정 아님). 같은 화면에서 두 variant를 순서대로 시작한다.
- 확인할 것: 권장 폴링 간격, 한 번에 실행할 수 있는 Run 수, 초과 시 응답(`409` 여부), 실행 한 번의 예상 소요 시간.
- 담당: 장근창.

<a id="oi-6"></a>
### OI-6 스크린샷 제공 방식·이미지 크기

- 임시 결정: 원본 이미지를 `GET /api/runs/{runId}/screenshots/{stepId}`가 `image/png`로 반환하고 프론트가 박스를 그린다.
- 확인할 것: 원본과 오버레이 이미지의 분리 저장 여부, 이미지 픽셀 크기와 `devicePixelRatio`, 응답에 `imageUrl`을 줄지 경로 규칙만 쓸지, `stepId`로 조회 가능한 시점.
- 담당: 이성집(캡처), 장근창(제공).

<a id="oi-7"></a>
### OI-7 bbox 좌표·scroll

- 임시 결정: viewport 기준 CSS 픽셀 `{x,y,width,height}`, 첫 화면(scroll 0)만 대상.
- 확인할 것: 스크롤한 화면의 후보를 다룰지, 좌표 기준이 스크린샷 왼쪽 위인지, GO_BACK 후보의 `bbox` 값.
- 담당: 이성집.

<a id="oi-8"></a>
### OI-8 Run 목록 조회

- 임시 결정: 목록 API 없이 이 브라우저에서 시작한 `runId`를 `localStorage`에 기록한다.
- 확인할 것: variant별 최신 Run 조회, 화면 3의 "최근 탐색 실행 기록"에 쓸 목록 API(`GET /api/runs` 등)의 필요 여부와 필터(`experimentKey`, `variant`).
- 담당: 장근창, 정자비.

<a id="oi-9"></a>
### OI-9 버전 표현

- 임시 결정: P0는 `variant`(`before`/`after`)만 쓰고 표시 이름 `v1 (변경 전)`, 변경 내용은 프리셋이 제공한다. Version 등록·관리는 `P1`.
- 확인할 것: `variant`와 `v1`·`v2` 이름의 대응, 변경 내용 문구의 출처, 이후 `versionId` 도입 계획.
- 담당: 장근창.

<a id="oi-10"></a>
### OI-10 Issue 종류·우선순위 기준·증거 형식

- 임시 결정: 종류 `CHOICE_AMBIGUITY`, `REPEATED_VISIT`, `EXTRA_STEPS`, 우선순위 `HIGH`·`MEDIUM`·`INFO`, 근거는 `evidence.summary` 문장과 `evidence.metrics` 수치.
- 확인할 것: 종류와 규칙 코드(`P0 Rule 1~3`) 목록, 우선순위 부여 기준과 임계값(엔트로피 기준 등), 발생 위치가 여러 단계일 때의 표현, 응답 정렬 기준.
- 담당: 정윤희.

<a id="oi-11"></a>
### OI-11 비교 지표·비교 불가 처리

- 임시 결정: 비교 응답이 지표 표(`metrics`)와 시작 화면 후보 대응을 모두 포함한다. 조건 불일치는 200 + `conditionsMatched=false`, 한쪽이 없으면 404.
- 확인할 것: `pathCost`(탐색 이동 비용)와 `goalPathProbability` 정의, 디자인의 `Conditional Entropy`와 `Model Latency` 제공 여부, `mismatchReasons` 값 목록, 비교 가능 조건(사이트·목표·페르소나·모델·단일 변인).
- 담당: 정윤희.

<a id="oi-12"></a>
### OI-12 후보의 확률·선택 병합, `semanticKey` 노출

- 임시 결정: `Candidate`에 `probability`와 `selected`를 서버가 합쳐 내려주고 `semanticKey`도 포함한다.
- 확인할 것: 후보 정보와 모델 응답(`probabilities`, `choice`)을 응답에서 합칠지 분리할지, `semanticKey`를 프론트에 노출해도 되는지(백엔드 전용으로 문서화돼 있음), GO_BACK 후보의 표현.
- 담당: 정자비(저장 형식), 이성집(후보 추출).

<a id="oi-13"></a>
### OI-13 저장된 실측 데이터 시연

- 임시 결정: 화면 배지는 `resultOrigin`(`MOCK`·`LIVE`·`SAVED_MEASURED`)을 그대로 표시한다.
- 확인할 것: 저장된 실측(`results/json`)을 API로 제공할지, 어떤 Run을 시연용으로 고정할지, 시연 중 `LIVE`와 섞이지 않게 하는 방법.
- 담당: 정자비.

<a id="oi-14"></a>
### OI-14 CORS와 다른 PC 주소

- 임시 결정: 프론트 `http://localhost:5173`, 백엔드 `http://127.0.0.1:8000`, 이미지는 경로만 받아 프론트가 `VITE_API_BASE_URL`에 붙인다.
- 확인할 것: FastAPI의 허용 출처 설정, 다른 PC에서 실행할 때의 허용 출처 추가 방법, 응답에 절대 주소를 담지 않기로 할지.
- 담당: 장근창.

<a id="oi-15"></a>
### OI-15 프리셋 응답

- 임시 결정: `GET /api/presets`가 사이트·목표·사용자 유형·모델·버전·입력 제한을 한 번에 반환하고 최대 탐색 횟수는 1~15(기본 8).
- 확인할 것: 목표·사용자 유형 ID 체계(`goalId`는 `refund` 확인됨), 모델 목록 필요 여부, 최대 탐색 횟수 범위와 기본값, 주소 검증에 쓸 사이트 정보.
- 담당: 장근창.

<a id="oi-16"></a>
### OI-16 실행 이벤트 로그·Playwright 상태·단계 시각

- 임시 결정: 해당 필드가 없으면 화면 영역을 숨긴다.
- 확인할 것: 단계별 실행 이벤트 로그와 Playwright 상태(클릭 중·완료)를 응답에 담을지, 단계 시작 시각(`startedAt`), 클릭 실패 시 표현.
- 담당: 정자비(기록), 이성집(브라우저 실행 상태).

<a id="oi-17"></a>
### OI-17 화면 이름 표시

- 임시 결정: 프론트가 `page.path`로 화면 이름(메인 홈, 고객센터 등)을 만든다.
- 확인할 것: 서버가 화면 이름을 줄지, 사이트별 경로-이름 목록을 프리셋에 담을지.
- 담당: 정자비.

<a id="oi-18"></a>
### OI-18 목표 판정 근거 노출

- 임시 결정: `Run.summary.goalReached`만 표시한다.
- 확인할 것: 판정 근거(`pathMatched`, `textVisible`, `successCondition`)를 응답에 담을지, 목표별 성공 조건을 프리셋으로 제공할지, 시안의 "DOM 마커 검증" 문구를 현재 판정 방식에 맞게 바꾸는 것에 대한 동의.
- 담당: 정자비.
